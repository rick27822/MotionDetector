## 1. 获取与运行

```sh
git clone --branch feat/chenkerui-ui-stage1 https://github.com/rick27822/MotionDetector.git
cd MotionDetector
cmake -S motiondetecter -B motiondetecter/build-p1 \
  -DCMAKE_PREFIX_PATH=/opt/homebrew/opt/qt \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build motiondetecter/build-p1 -j 4
ctest --test-dir motiondetecter/build-p1 --output-on-failure
motiondetecter/build-p1/motiondetecter.app/Contents/MacOS/motiondetecter
```

以上是本次 macOS arm64 / Qt 6.11.0 的验证方式。Qt Creator 也可直接打开 `motiondetecter/CMakeLists.txt`。Windows 需选择自己的 Qt 6 桌面 Kit；本次没有执行 Windows 验证。

运行后点右上角 **姿态回放 → 12次动作合成样例**，约 9.6 秒完成。也可以选“打开姿态文件…”加载交接 JSON / JSONL。停止后再开始，会从文件首帧重放并创建新会话。回放结束后继续等待会显示数据中断，已经完成的次数保留到停止或断线为止。

本地已生成的应用在 `output/PoseLab-P1.app`；该生成目录不入 Git，其他成员需要构建。重新打包：

## 2. 可重复的主程序验收

从仓库根目录执行，先创建输出目录：

```sh
mkdir -p output/p1-check
QT_QPA_PLATFORM=offscreen \
  motiondetecter/build-p1/motiondetecter.app/Contents/MacOS/motiondetecter \
  --data-dir output/p1-check/data \
  --replay motiondetecter/fixtures/realtime-12reps.jsonl \
  --replay-report output/p1-check/12reps.json
```

程序按文件时间间隔调用正式控制器，结束后输出结果 JSON 和 `12reps.json.png`，然后退出。预期 `completedReps=12`、`droppedFrames=0`。样例只有合成角度，没有人体关键点或视频，所以中央显示角度而不伪造骨架；支持包含关键点的姿态 JSON。文件上限 16MB，仅用于短片段联调。

`--replay-report` 只在回放自然结束时生成；交互停止/断线时不产生成功报告。没有此选项时程序保留在页面，可继续观察无帧超时或重新开始。

## 3. 真实 poseReady 的接收位置

- 装配入口：`MainWindow::beginRealtimeInput(sourceName)`，在 GUI 线程、输入源实际就绪后调用。返回本次检测会话 token；此调用只登记姿态源，不会建立手机网络或启动模型。
- 单帧接收：`RealtimeController::onPoseReady(const core::PoseResult &, const QString &token)`。GUI 线程调用时立即处理；其他线程调用时进入有界邮箱，由 GUI 线程处理。
- 服务调用：`RealtimeController::accept()` 通过上游 `adaptRealtimePose<core::JointAngle>` 适配，同一个常驻 `RealtimeAnalysisService` 调用 `processPose()`。
- 展示：`RealtimePage::refresh()` 从控制器读取同一帧姿态与同一份结果，更新骨架、HUD、提示文字、进度条和累计次数。
- 断开入口：`MainWindow::endRealtimeInput(token)`，在 GUI 线程调用；旧 token 的断线回调会被忽略。

接线示意如下。`poseEngine` 和 `pose::IPoseEstimator` 是待装配的姿态模块对象及其信号声明，并非本分支已实例化的后端。真实信号须为 `poseReady(const core::PoseResult &)`：

```cpp
// 在 GUI 线程装配；shared_ptr 让连接句柄与以下回调保持相同生命周期。
auto live = window.realtime();
auto binding = std::make_shared<QMetaObject::Connection>();
QObject::connect(live, &ui::RealtimeController::sessionStarted, live,
    [live, poseEngine, binding](const QString &token) {
        QObject::disconnect(*binding);
        *binding = QObject::connect(poseEngine, &pose::IPoseEstimator::poseReady,
            live, [live, token](const core::PoseResult &pose) {
                live->onPoseReady(pose, token);
            }, Qt::DirectConnection);
    });
const QString token = window.beginRealtimeInput("MoveNet 姿态输入");
// 输入源断开信号应先回到 GUI 线程，再调用 window.endRealtimeInput(token)。
```

`sessionStarted` 每次启用检测都会发出，因此必须更新绑定里的 token；不能在每帧回调时临时读取当前 token，否则旧源迟到帧会被误认为新会话。真实源重连/换源时重新调用 beginRealtimeInput，时间戳与帧号可从新会话起点重新计数。销毁窗口前应先停止并等待生产线程退出，不能让生产者继续访问已销毁的接收对象。

邮箱只保留最近 1 帧，最多挂起 1 个 GUI 唤醒事件，避免逐帧排队。覆盖计入 droppedFrames。超载时可能漏掉动作阶段并少计，因此此策略不证明高负载下的计次完整率；需要在真实源测试掉帧和处理耗时。服务本身是常量时间、常量状态的操作，本轮在 GUI 线程串行调用；未进行真实帧率或响应延迟测量。

## 4. 会话、时钟和生命周期约定

- 检测会话使用独立 UUID，不复用 P4 的样例会话 ID，也不等待开始录像。真实录制 ID 与检测 ID 的映射留给录制接入时处理。
- 保留 pose.timestampMs 的原始单调毫秒，不减录像起点、不换算为 Unix 时间。
- 当前没有统一采集时钟，因此按陈艺夫的备选方案：每个非重复、合法输入到达时，锚定其源时间戳及本地 QElapsedTimer；每 50ms 用“源时间戳 + 本地经过时间”调用 poll。超过 500ms 无新姿态即覆盖旧提示并清空画面数据。首帧一直不来，也会在超过 500ms 后提示输入缺失。
- 工作线程进入邮箱时记录接收时间。等待 GUI 超过 500ms 的帧按失效姿态处理，不能触发补计。该计时仍无法测量进入 onPoseReady 之前的相机/推理队列延迟；未来需要统一采集时钟和源帧关联。
- detected=false 强制角度不可用；有效掩码保留合法 0°；非有限或越界角度不用于显示或计次。重复/倒序时间和帧号交给上游服务拒绝，同时清除当前显示姿态。
- 同一检测会话中短暂丢人/超时：保留已经完成的次数，打断未完成动作；恢复后先重新站立。
- 停止或断线：保留结束前的 token/count，reset、清空次数/提示/姿态并撤销 token，再通过 sessionEnded(token, count) 供后续存储接收。当前未将该信号写入正式数据管理服务。
- 重连/重新开始/换文件：创建新 UUID，次数归零。旧 token 的帧、待处理邮箱内容、旧断线回调均不能覆盖新会话。
- 联调时禁用视频录制与样例设备接入，防止把合成会话当成真实录制。镜像/骨架/角度开关仍只影响绘制，P3/P6 尚未向真实姿态源下发参数。
