限制仍然存在：指标固定、`simulated=true`；会话和配置仅内存存储；导出返回 `NotImplemented`。这次通过证明 Mock 契约能运行，不证明真实评分、持久化或导出完成。

### 3.2 姿态 v1.1

执行：

```sh
cmake -S /tmp/motiondetector-handoff-review/PoseModule-v1.1-src \
      -B /tmp/motiondetector-handoff-review/build-pose \
      -DCMAKE_PREFIX_PATH=/Users/cherry/Qt/6.5.3/macos \
      -DPOSE_PREGENERATED_MOC=OFF
cmake --build /tmp/motiondetector-handoff-review/build-pose -j 2
```

实际结果：配置成功；编译失败于 `modules/pose/OnnxBackend.cpp:198`：

```text
cannot initialize a parameter of type 'const char *'
with an rvalue of type 'const value_type *' (aka 'const wchar_t *')
```

源码在 Mac 仍使用 Windows 宽字符模型路径；运行库搜索名固定为 `onnxruntime.dll`。当前完整包不能直接在本机编译。未修改源码重试，未执行真实推理。

建议修复：Windows 用宽字符路径，macOS/Linux 用有效 UTF-8 路径；按平台搜索 `.dll/.dylib/.so`；提供匹配 arm64 与 ONNX C API 的运行库；对当前 Qt Kit 重新生成 moc。

## 4. 必须处理的差异

### 公共类型

| 项目 | 分析 M0 | 姿态 v1.1 | 处理方向 |
| --- | --- | --- | --- |
| namespace | `motion` | `core` | 保留供应方边界，UI 使用规范类型，显式适配 |
| PoseResult | 七组命名角度，含 degrees/valid | 33 关键点槽、12 路数组、validAngles、frameId | core → motion 有损转换只供旧分析接口；原始姿态另存 |
| 时间戳 | 会话内毫秒 | 本次采集起算毫秒 | 录制时扣统一基准，保留原时间戳及视频 PTS 映射 |
| 会话 ID | std::string | qint64 | 初版 UI 用不透明 QString ID，禁止强制转数字；适配层维护持久映射 |
| 对称性 | 建议 0~1 | 0~100 | 在服务边界统一为显示百分比，禁止重复乘100 |
| 分数 | qualityScore，0~10，模拟 | score，0~10 | 页面按已确认方案展示百分制换算，并保留模拟标记 |
| 配置 | AppConfig 字段较少 | PoseConfig/CaptureConfig/AppSettings | 应用层 ConfigSnapshot 组合，避免旧 Mock 丢失其他字段 |

两套文件都叫 `core/types.h`。即使命名空间不同，也可能因 include 搜索顺序取错头文件。导入时需要隔离 M0 私有类型路径并保留供应方补丁记录，不能把两个根目录无差别加入所有 target。

### 姿态实现与说明

- 真实后端实际为 YOLOv8-pose / COCO-17，不是三种真实模型均已实现。`PoseConfig.model` 和 `PoseResult.modelName` 不能独立证明实际后端。
- 未设置模型路径或加载失败时会回退 SyntheticBackend。界面必须显示实际后端及演示状态，不能仅看 `loadModel()` 返回 true。
- `loadModel()` 会提前把 loaded 设为 true；应补充真实后端就绪/失败/回退通知，并验证配置应用完成事件。
- OnnxBackend 中未见 GPU execution provider 启用路径；useGpu 字段不能证明 GPU 生效。NMS 参数也不能直接按“已支持”展示。
- `PoseStats.fps` 按平均推理耗时倒数计算，不是实测输出吞吐；主界面帧率应另计数。
- `frameId` 在 estimate 时递增，不等于相机输入帧编号；关联优先使用采集会话标识和时间戳，建议显式携带 sourceFrameId。
- Worker 内有界队列不限制外层 Qt queued invoke 的事件数量；需补入口限流与压力验证。
- 流切换、重置时间戳、配置变化、退出和长时推理的线程生命周期都需联调；不得只靠一次 demo 通过。
- Mat 使用共享缓冲，但仍有可写入口；toImage() 实际深复制。要明确发布后不可修改，不能笼统宣称整条管线零复制。
- v1.1 已按实际画面宽高比校正角度。UI 不重复校正或滤波。无效判断使用 validAngles/hasAngle，不能按 angle > 0。

### 样例数据

- 三帧完整样例时间为 0、1716、2640 ms；可用于关键点/HUD/解析测试，不足以构成连续视频骨架回放。
- v1.1 JSONL 实际 382 行，t 为 0~12573 ms，严格递增；不含 keypoints。
- Input 包与 v1.1 包的 `core/types.h`、IPoseEstimator.h 字节一致；JSONL 文件字节不一致，不要因版本名相近就假定所有样例相同。
- 导入器兼容中文和 ASCII 角度键，内部转换为枚举；新生成数据只写统一格式。若同一通道的两种键同时存在且冲突，报错而非静默取一个。
- 样例为合成数据，不能用于证明真人识别、准确率、帧率或评分质量。
