## 1. 交付目标、已确认决策与范围

交付由两个节点组成：

1. **UI 可独立验收**：六页与设计稿高度一致；导航、控件、加载/空/错误状态完整；通过样例和 Mock 验证数据流。
2. **真实系统验收**：真实手机画面进入 Qt；实际模型产生随真人动作变化的关键点与角度；支持录制、含骨架的回放和真实服务支持的分析/导出。

第二项纳入正式推进计划，但依赖队友尚未提供的相机/手机连接、录制、存储和分析实现，以及 Mac 运行库和模型。UI 成功不等于这些外部能力完成；若依赖未交付，必须保留缺项清单，不能把完整系统记为通过。

已确认：继续 Qt 6/C++ Widgets；主要在 Mac 验收；保持原六页布局、配色和视觉层级；数据语义优先真实。百分制显示、真实 YOLO 后端名称、未实现控件禁用、躯干角度按实际契约展示，均已获用户接受。

技术选择：

| 项目 | 决策及理由 |

## 4. 视觉还原方案：把“高度一致”变成可检查结果

### 4.1 固定基准

- 以 PDF 六页的 1440×900 内容区为基准，不包含 macOS 原生标题栏。
- 截图使用相同逻辑尺寸、固定设备像素比转换规则。首次在 Mac 固定字体家族、字号、字重、Qt 样式与图标集。
- 视觉验收模式使用确定性 fixtures、固定页面状态、固定播放时刻、暂停动画。正常运行时不锁死真实数据。
- 不把整页截图当成界面，也不烘焙按钮和骨架到背景图；各控件必须可交互。

### 4.4 素材、视频和骨架

- 目前只有 PDF 和一张1536×1024项目图片。可复用原图作视觉占位，并核对 PDF 内的裁剪与取景；真实模式显示实际视频。
- 视频支持 Fit 与 Cover 两种有明确变换的模式：参考截图选择接近设计稿的取景，真实检测默认完整保留人体；画面和骨架共享同一矩阵与裁剪。
- 不使用包内 SceneRenderer 的深蓝色合成人形替代设计稿的人像素材来通过视觉验收。合成场景只用于时序联调。
- 将 SkeletonStyle 的左右/中心线统一为青色，调细线宽、节点半径与光晕，以接近稿件；保留真实拓扑和有效点规则，不照抄稿件中不准确的几何位置。
- 图标选统一线性 SVG，必要时按 PDF 轮廓重建；字体没有源文件时选可部署中文字体并验证行宽。无法保证未知字体渲染逐像素一致。

### 4.5 建议视觉验收阈值

以下是待实施时采用的项目目标，不是已经取得的结果：

1. 六页1440×900截图全部保留基准、当前、50%透明叠图和差异图。
2. 侧栏/顶栏/卡片边界等主要锚点目标偏差≤2逻辑像素；对齐、换行和按钮尺寸逐项复核。
3. 纯色区域采用已提取的色值；文字无截断、溢出，强调色与层级一致。
4. 对可比较静态区域统计像素误差；字体边缘允许小幅抗锯齿容差。SSIM 等数值仅作辅助，不以一个“相似度百分比”代替验收。
5. 真实视频区域、必要的真实文案和时间动态值用预先声明的遮罩/语义规则比较；遮罩不能覆盖导航、按钮、卡片边框、布局或错误提示。
6. 交互状态单独检查 hover/pressed/focus/disabled/loading/error，不能只有默认态好看。

## 5. 接口整合与数据流

### 5.1 正常运行链路

```text
手机网页/连接服务（孙梁提供）
    → Python camera_module
    → camera_runner（控制/帧协议）
    → PythonCameraService（QProcess，后台增量解析）
    → FrameEnvelope + core::MatPtr
       ├→ VideoView（显示最新或匹配帧）
       ├→ PoseEngine.submitFrame → poseReady
       │   ├→ HUD/骨架/有效角度
       │   └→ 录制元数据与 AnalysisM0Adapter/真实分析
       └→ 独立录制链路（孙梁负责编码能力）

完成录制 → SessionRepository → 回放/分析/导出
```

### 5.2 Python 桥接最小方案

优先通过 QProcess 使用受控 Python 解释器启动 `camera_runner.py`。GUI 不在主线程轮询 Python，也不通过 shell 拼接启动命令。首版使用进程管道，避免额外建立网络端口。

- stdin：按行 JSON 命令，含 requestId、start/configure/stop、参数。
- stdout：固定长度前缀 + JSON 头 + 原始像素块的二进制消息；头含版本、类型、payload长度、sessionId、sourceFrameId、timestampMs、width/height/stride/pixelFormat和变换矩阵。具体字节序与字段上限在 protocol.md 冻结。
- stderr：日志；禁止普通 print 污染二进制 stdout。
- Qt 接收端增量解析，处理半包、粘包、进程退出和超时；验证长度、尺寸、stride、像素格式与会话，限制消息/缓存大小。
- 背压：Python 和 Qt 两边限制待发/待解析帧数，显示保留最新值；繁忙时按协议丢弃完整旧帧，不把半帧混入流；录制使用独立策略。
- 不逐帧 base64，不为每帧写磁盘图片。720p BGR30约83MB/s，1080p约187MB/s，仅为像素载荷估算，需实测复制开销。
- 首先720p验证；若管道复制影响吞吐，保留控制协议，将帧载荷替换为共享内存/帧池。不要一开始同时实现两种传输。

camera_interface.py 只提供 received_at（Unix秒），无法安全与单调毫秒混算。由相机进程在实际采集入队边界记录 monotonic 时间，并作为 packet 的稳定字段传出；同一 packet 反复 latest 不能重新打时间。received_at 只用于日志。若完整包不能修改，桥接生成的时间必须标记为“桥接接收时刻”，不可据此声称测得拍摄端到端延迟。

### 5.3 姿态和旧分析适配

- UI 以 `core::PoseResult` 为规范输入；固定33槽，不要求33点全部有效。
- `AnalysisM0Adapter` 根据枚举提取七路角度，保持 valid 位，检查有限数，转换字符串和时间戳；不再滤波。
- 旧 motion::PoseResult 不含关键点。转换结果只送旧分析服务，完整 core PoseResult 另存用于回放。
- 样例导入兼容中文与 ASCII 角度键、validAngleMask/validMask、null；新数据只使用一个版本化 schema。掩码与字段冲突时拒绝或给出明确诊断。
- 流重启创建新 generation/session，清理旧帧缓存和推理状态。旧回调携带旧 generation 时丢弃，避免时间戳重置后串流。
- 推理输出 frameId 是处理计数，不视为源帧 ID。通过源会话+时间戳关联，并请求姿态侧透传 sourceFrameId。

### 5.4 配置、能力与结果语义

- SettingsController 是唯一应用入口；P3/P6 维护草稿，共享当前有效 ConfigSnapshot。
- Snapshot 组合 CaptureConfig、PoseConfig、AppSettings及schema版本；旧 Mock AppConfig 只映射它能表示的字段，其他字段不得静默丢弃。
- 流程为校验 → 模块应用并确认 → 保存 → 更新共享状态。保存失败保留“已应用未保存”状态；模块部分失败回滚或明确显示失败字段。
- 不支持的 GPU、NMS、模型、开机启动、检查更新、JSON/MP4“角度导出”保留合理位置并禁用/说明；不能只把设置值写入文件就显示已生效。
- 显示分数=0~10原始分×10；例如8分显示80，并通过说明标注“由10分制换算”。评分等级与建议来自服务；模拟评分始终标注模拟。
- 对称性入口归一为0~100显示范围，旧M0的0~1仅在适配层换算一次。
- 躯干按0~90°无符号倾角展示，不从稿件复制-31.4°；最大/最小膝角、平均/峰值角速度使用真实语义标签。

### 5.5 录制、回放和完整姿态存储

相机接口没有录制方法，必须由孙梁补录制服务能力或提供独立编码实现。UI 不假设 start() 就会录像。约定 startRecording、stopRecording、started/finalized/failed、实际路径、编码状态与时间映射。

每个会话建议保存：

```text
session-id/
├── manifest.json              # schema、模型/后端、配置、起点、时长、文件与状态
├── video.mp4
├── poses.jsonl                # 完整33槽姿态、valid、源时间、sourceFrameId
├── frame-map.jsonl            # 视频PTS或编码帧号与源时间/源帧映射
└── angles.csv                 # 可由完整姿态生成；由数据服务导出
```

此文件布局是拟议录制契约，需与孙梁/陈艺夫确认。数据库可索引这些文件，不要求把所有关键点放进现有 SessionRecord 结构。

- 录制起点取实际录制首帧事件，不取按钮点击或首个晚到的推理结果。
- `t = sourceTimestamp - recordingOrigin`，保存完整原始标识和视频PTS映射；CFR编码重复/丢帧时也必须保持映射，不用 `frameId/30` 猜时间。
- 停止后等待编码与元数据完成再入库；失败保存 partial 状态或明确清理策略，不能列为完整会话。
- QtPlaybackService 用 QMediaPlayer + QVideoSink 输出画面，播放器位置驱动曲线与姿态匹配；验证 Mac 解码与权限。
- 只在原始帧时间/视频PTS匹配且未超过容差时画姿态，缺失就显示暂无匹配，不能无限保留旧骨架。
- 保存成功后 P4/P5 列表更新；会话ID视为不透明标识，不强转 qint64。

## 6. 六页的具体开发与验收

### P1 实时检测

**文件**：RealtimePage、VideoView、AngleHUD、DetectionController。

步骤：①按稿布局视频、右侧角度/参数/提示卡、底部控制；②使用固定人像与fixtures做截图；③接Mat和poseReady；④统一fit/cover、mirror、rotation/crop矩阵；⑤接检测/停止/录制状态机；⑥显示实际后端、输出帧率、推理耗时与连接状态。

状态：NoDevice、Connecting、Ready、Detecting、Recording、Stopping、Error。各按钮只允许合法迁移；切页不隐式停止，退出先结束录制和线程。

验收：画面比例正确；青色骨架/节点/HUD样式接近稿；0°合法可见；无效角度显示“—”；无检测清除或标识过期骨架；实际移动能带动姿态；录制未成功不显示REC；实际输出fps与推理耗时分开计量。

### P2 设备连接

**文件**：DevicePage、DeviceCard、DeviceController、PythonCameraService。

步骤：①还原二维码卡、说明、三设备样例、四格信息；②设备ID驱动列表；③接发现、配对、连接、断开、刷新；④手机扫码用真实有效链接生成二维码；⑤处理权限/同网/过期/断流；⑥状态同步侧栏与P1。

验收：刷新/连接有加载反馈，重复点击受控，失败可重试；二维码能被手机识别并打开正确地址；真实连接结果才显示已连接。Mac摄像头/LAN/防火墙、手机HTTPS或安全上下文、局域网证书与同Wi-Fi由孙梁提供可运行方案并实测，不能只生成二维码。

### P3 检测配置

**文件**：DetectionConfigPage、ModelCard、SliderField、ToggleField、SettingsController。

步骤：①还原三模型卡的布局与选中边框；②按真实能力修正文案/禁用未实现项；③置信度/NMS/EMA滑条绑定草稿，NMS不支持时禁用；④关键点按统一33槽mask和预设显示；⑤保存时应用并确认，恢复默认恢复草稿；⑥与P1/P6同步并验证重启恢复。

真实YOLO后端使用卡片样式展示实际名称，不把旧MoveNet名称用于伪装。未实现三模型切换不列为功能通过。EMA `alpha` 越小越平滑，滑条说明必须一致。

验收：UI不发生多选；无效/不支持项不误提交；已保存与未保存明确；后端失败不覆盖有效配置；录制中不允许破坏录制的模型/采集变更。

### P4 录像回放

**文件**：PlaybackPage、SessionCard、VideoView、ChartView、SessionController、QtPlaybackService。

步骤：①还原播放器、底部进度/倍率、曲线、会话列表；②用合法短视频验证解码和拖动；③加载完整poses文件与frame-map；④以positionMs联动骨架、曲线游标；⑤实现暂停、seek、0.5/1/2倍速等约定选项；⑥处理文件丢失、无姿态、损坏会话。

验收：拖动时手柄不被自动刷新抢回；seek清理旧回调；暂停不继续走游标；倍速下视频/骨架/曲线一致；视频可独立打开；连续角度JSONL只用于曲线测试，不能用三帧姿态假装连续骨架。

### P5 数据分析

**文件**：AnalysisPage、ChartView、ScoreRing、SessionController、AnalysisM0Adapter/DataM0Adapter。

步骤：①四KPI卡、双曲线、评分环、历史条和导出按钮还原；②接已适配的M0曲线/模拟分数，并明确模拟；③接真实分析结果；④统一百分制/对称性/角速度语义；⑤历史对比绑定明确会话；⑥导出CSV、报告并检查真实落盘。

验收：缺值断开曲线，不连到0；长期序列只做显示降采样，分析用完整数据；会话切换丢弃旧分析结果；NotImplemented显示未实现；CSV/报告实际存在且可打开。报告优先HTML（易检查），如要求PDF则由导出服务提供并进行Mac打开验证。未实现PDF时不能改扩展名冒充PDF。

### P6 系统设置

**文件**：SettingsPage、ToggleField、SliderField、SettingsController。

步骤：①按五卡布局；②通用字段绑定应用设置；③采集参数下发相机桥；④推理设备/线程/能力从后端获取；⑤路径通过目录选择器、可写验证与持久化；⑥关于显示实际版本，检查更新等未实现项明确禁用。

验收：配置初始化不会触发意外保存；P3/P6不互相覆盖；不存在的GPU不显示启用；权限拒绝/目录不可写可理解；保存后退出重启一致。保留设计稿视觉，修正“MP4为角度格式”等语义。

| 组件/部分 | 具体实现 |
| --- | --- |

| IO与分析 | 独立工作线程/任务队列，服务若非线程安全则串行调用；结果携带requestId/sessionId |

服务所有权在main/AppServices统一管理，注入页面的服务必须比页面寿命长。引入工作线程后补Qt元类型注册。避免直接调用已moveToThread对象的方法误以为自动切线程。
